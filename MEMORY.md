| 2026-09-28 | Strict boundary isolation to project root | User directive: no access behind/outside mvp directory | Cross-directory linking or reference |
| 2026-09-28 | Service/Repository abstraction for all data access | Phase 0 & 1 requirement: API-ready architecture with seamless transition from browser mock to future backend | Hardcoded data in React components, direct mock imports in UI |
| 2026-09-28 | Separate Role Permissions from Access Scope | CTMS domain requirement: a role's permissions (e.g. View Patients) must be decoupled from data scope (e.g. Assigned Site vs Assigned Participants) | Flat global permissions |
| 2026-09-28 | Browser-only synthetic data execution | Security & compliance: no clinical data leaks, zero external telemetry or cloud dependencies | External mock APIs, unvetted third-party services |
| 2026-09-29 | Vite 6 + React 19 + TypeScript + Tailwind 3.4 | Standard client-side SPA architecture, fast HMR, reliable verification ladder, native ES modules | SSR frameworks with server requirements |
| 2026-09-29 | Dedicated Participant Detail Route (`/pi/patients/:participantId`) | Direct deep linking and clear breadcrumb navigation fitting existing routing architecture | In-page modal or nested tabs |
| 2026-09-29 | Deterministic Reference Date Provider (`getReferenceDate()`) | CTMS operations reproducibility: enables stable calculation of visit windows and operational statuses (DUE, OVERDUE, MISSED) across automated tests and browser UI | Dynamic unmocked `new Date()` |
| 2026-09-29 | Protocol Target Offset vs Allowable Window Separation | Clinical trial accuracy: a visit has a target date (e.g. Day 28) and an allowable compliance window ($\pm3\text{d}$); status transitions to OVERDUE or MISSED after window closure | Treating target date as hard cutoff without window |
| 2026-09-29 | Decoupling Severity, Seriousness, and Causality | ICH-GCP E2A / E6 clinical regulatory compliance: Severity describes symptom intensity (Mild/Moderate/Severe), Seriousness is a defined regulatory outcome (Death/Hospitalization/Disability/Life-threatening/Medically Important), and Causality is a medical assessment (Unlikely/Possible/Probable/Definite). Severe $\ne$ Serious. | Conflating severity with seriousness, auto-deriving seriousness from severity |
| 2026-09-29 | Non-Diagnostic Human-in-the-Loop Causality Assessment | Medical ethics & regulatory law: CTMS prototype must not perform automated clinical diagnosis; Causality assessment remains an investigator-entered and PI-signed medical determination. | Automated AI diagnosis or algorithmic causality scoring |
| 2026-09-29 | Protocol Deviation Scoping (`PARTICIPANT` vs `SITE` vs `STUDY`) | Clinical trial protocol deviations occur at subject level (e.g. out-of-window visit, missed test), site level (e.g. temperature excursion in drug storage, missing calibrated equipment), or study level (e.g. delayed ethics amendment submission). `participantId` is strictly optional and only populated when `scope === 'PARTICIPANT'`. | Forcing a dummy participant ID onto site-level deviations, restricting deviations to participants only |
| 2026-09-29 | Decoupling Deviation Classification from Safety Severity | ICH-GCP E6 (R2) compliance: Deviation classification (`MINOR`, `MAJOR`, `CRITICAL`) measures protocol / GCP non-compliance and impact on trial integrity or subject safety, while AE Severity (`MILD`, `MODERATE`, `SEVERE`) measures clinical symptom intensity. Protocol deviations must never be styled or categorized as Adverse Events. | Sharing severity types between safety and compliance, conflating protocol deviations with adverse events |
| 2026-09-29 | CAPA Status Independence from Deviation Lifecycle | CAPA (Corrective and Preventive Action) represents an operational mitigation workflow (`NOT_REQUIRED`, `PENDING`, `IN_PROGRESS`, `COMPLETED`, `OVERDUE`) that runs alongside or triggers lifecycle progression (`REPORTED`, `UNDER_REVIEW`, `ACTION_REQUIRED`, `CAPA_IN_PROGRESS`, `RESOLVED`, `CLOSED`). Resolving CAPA moves lifecycle towards resolution while preserving CAPA historical record. | Conflating CAPA status with deviation status into a single field |
| 2026-09-29 | Explicit Lifecycle Transition Validation | Operational compliance integrity: Enforce explicit state transition map (`REPORTED -> UNDER_REVIEW/ACTION_REQUIRED/RESOLVED`, `UNDER_REVIEW -> ACTION_REQUIRED/CAPA_IN_PROGRESS/RESOLVED`, `ACTION_REQUIRED -> UNDER_REVIEW/CAPA_IN_PROGRESS/RESOLVED`, `CAPA_IN_PROGRESS -> RESOLVED/ACTION_REQUIRED`, `RESOLVED -> CLOSED/UNDER_REVIEW/ACTION_REQUIRED`, `CLOSED -> terminal`) to prevent illegal state jumping (e.g. closing an unresolved deviation directly from REPORTED). | Unconstrained status mutations |
| 2026-09-29 | Audit Claim Renamed to Audit Metadata | Truth in advertising & regulatory accuracy: UI cards and reports only contain static record creation, review, and resolution timestamps and authorship, not a tamper-proof cryptographic or append-only audit trail. | Claiming GCP audit trail compliance without an actual event log engine |
| 2026-09-29 | Decoupled Role Permissions from Access Scope & Derived Effective Permissions | CTMS ICH-GCP domain rule: A role defines WHAT actions a user can perform (controlled 24-permission catalog across 9 modules), while Scope defines WHERE those actions apply (`studyId` + `siteId`). Effective permissions are dynamically derived as the union of active role permission IDs in scope, with no duplicated static grant tables. System roles are immutable templates; cross-site queries are strictly isolated. | Monolithic IAM roles with embedded site IDs, static hardcoded effective permission lists, global unscoped roles |
| 2026-09-29 | Controlled Task Lifecycle & Approval Gate Enforcement | Clinical trial operations: Tasks with `requiresApproval === true` cannot bypass PI oversight and transition directly to `COMPLETED` from `IN_PROGRESS`; they must follow `SUBMITTED -> UNDER_REVIEW -> APPROVED -> COMPLETED` (or revision loop `UNDER_REVIEW -> REVISION_REQUIRED -> IN_PROGRESS`). Cross-site and inactive staff task assignments are strictly rejected. | Unconstrained task completion, arbitrary status jumping |
| 2026-09-29 | Deterministic Expiry Engine & Standardized Horizons | CTMS reproducibility: `calculateDocumentExpiryState()` evaluates against reference date `2026-09-29` with strict 30-day expiring-soon threshold and UTC midnight normalization for cross-platform stability. | Unmocked dynamic `new Date()` calculations. |
| 2026-09-29 | Metadata Document Control Architecture | Security & MVP fidelity: Browser-only MVP tracks controlled document metadata, versions, and audit trails without external binary storage or cloud upload endpoints. Historical versions are immutably preserved as SUPERSEDED. | Physical binary blob storage in client indexedDB or third-party cloud S3. |
| 2026-09-29 | Operational Action Required Compound Rule | GCP compliance: Documents flagged as `isRequired === true` trigger Action Required when currently `EXPIRED`, `DRAFT`, or lacking an active valid version. | Checking only expiry date regardless of whether document is mandatory. |
| 2026-09-29 | Browser Object URL & Simulated File Generation for Downloads | Browser MVP file management: Enables realistic drag-and-drop file uploads, metadata extraction, tab previews, and downloads without external backend storage or cloud egress. | Alert dialogs or external cloud file providers. |
| 2026-09-29 | Reporting via Domain Service Aggregation (Zero Duplicate State) | CTMS data integrity: Reporting layer (`IReportRepository`, `reportService`) aggregates directly from underlying domain services (`participantService`, `visitService`, `safetyService`, `complianceService`, `taskService`, `documentService`). Never creates a second source of truth. | Independent report tables or duplicating domain storage in report repositories. |
| 2026-09-29 | Browser-Local Deterministic CSV/JSON Export with BOM & Audit Disclaimer | Regulatory & security standards: CSV exports prepend UTF-8 BOM (`\uFEFF`) and RFC 4180 escaping so Excel renders cleanly. Both CSV and JSON outputs embed standardized regulatory disclaimer ("Generated from CTMS operational records for review/export. Not a regulatory filing.") and metadata. Zero cloud export services. | Backend CSV generators, unescaped raw string concatenation. |
