## 2. Decisions
- **Data-Model-First Foundation**: Designed full field-level data dictionary and entity-relationship models before building CRUD or APIs.
- **Organization Model**: CRO and Sponsor modeled as canonical `organizations` table records with `organization_type` enum (not plain strings). Studies reference `sponsor_org_id` and `cro_org_id` foreign keys.
- **Derived Portfolio Analytics**: Dashboard counters (Total Studies, Active Studies, Delayed Studies, Site Count, Actual Enrollment, Screen Failure Count) are computed dynamically via SQL queries on canonical records. Zero redundant counters stored.
- **Controlled Lifecycle State Machines**: Onboarding (`draft` -> `submitted` -> `under_review` -> `approved` [activates organization] / `returned` / `rejected`), Study (`draft` -> `planned` -> `active` -> `suspended` / `completed` / `terminated`), and Participant lifecycles are enforced through state-machine transitions that reject invalid jumps.
- **Cryptographic Audit Trail**: Hash-chained audit logging (`audit_logs`) computing SHA-256 over `(previous_hash + action + resource_type + resource_id + timestamp)` with an automated verification endpoint (`/api/v1/audit/verify`) for tamper detection.
- **Reusable Site Entity**: Multi-centric study conduct enabled through `sites` and `study_sites` junction table with unique constraint `(study_id, site_id)`.
- **Clean API Routing**: Aggregated under `/api/v1/` prefix with modular domain routers (organizations, studies, sites, participants, safety, compliance, documents, portfolio, audit, users).
